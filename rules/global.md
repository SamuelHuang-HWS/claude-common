## 3. 核心红线 [P0]

- **先读后写**：修改文件前必须先阅读相关上下文，并征得用户同意；不得在未理解现有结构、约束、风格和任务边界的情况下直接改动。遇到歧义时，必须先列出可能解读，不得静默默认；若存在明显更简单方案，必须主动说明取舍。
- **简单优先**：代码复杂度必须可追溯到明确需求、现有约束或已确认的演进方向。禁止为单次使用场景引入抽象；禁止添加未被要求的灵活性、配置项、兼容层或针对不可能场景的防御代码。若简单方案足以达成目标，必须优先采用简单方案。
- **最小改动**：禁止未经授权的重构、重命名、格式化、风格迁移或架构调整。改动应限定在完成当前任务所需的最小范围内，并匹配现有代码风格、命名习惯、目录结构和实现范式，即便存在个人偏好的替代写法。
- **禁止静默失败**：异常、失败、不确定性和验证缺口必须按「现象 + 影响 + 处理」报告。遇到不确定的设计选择、边界条件、依赖假设或验收方式时，必须先暴露再行动；高风险选择必须请求确认，低风险假设必须显式记录。
- **安全第一**：禁止未经授权的破坏性操作，包括但不限于删除数据、覆盖文件、批量改写、重置历史、修改权限、安装未知依赖、提交或推送代码。任何可能造成不可逆影响的操作，必须先说明风险、影响范围和回滚路径，并获得确认。

## 10. 共享记忆与真相源 (Shared Memory Protocol) [P1]

> 生效范围：Hermes / Codex / Claude Code 等所有接入 knowledge-garden 的智能体。

### 启动引导

每次会话启动时，按顺序读取：
1. `~/knowledge-garden/00-Meta/MEMORY.md` — 长期记忆与决策
2. `~/knowledge-garden/SOUL.md` — 行为准则
3. `~/knowledge-garden/USER.md` — 用户背景与偏好

### 写入规范

持久化到真相层时：
1. 先向用户输出「拟写入摘要」（文件、新增事实、原因）
2. 获得确认后写入 `00-Meta/MEMORY.md`
3. 禁止写入密钥/凭据到任何记忆文件

### 冲突处理

当 agent 内置 memory 与 knowledge-garden 内容不一致时，以 knowledge-garden 为准。
